GUI-Based Lab Exercises

10 Labs

These exercises guide you through real configuration tasks on the Cisco 9800 WLC WebUI. Each lab includes a scenario, step-by-step GUI navigation instructions, expected results, and a CLI verification command. Complete them in order for a progressive learning experience — later exercises build on earlier ones.

1

Create a Corporate WPA3 SSID with Central Switching

Easy
Scenario: Your company needs a new corporate SSID called Corp-WiFi6 using WPA3 security. All client traffic must be centrally forwarded to the WLC and placed on VLAN 100.
  1. Navigate to Configuration › Wireless › WLANs and click + Add.
  2. Set Profile Name = Corp-WiFi6, SSID = Corp-WiFi6, Status = Enabled.
  3. Click the Security tab › Layer 2. Select WPA3 Personal (SAE). Set a strong passphrase. Enable PMF = Required (mandatory for WPA3).
  4. Click Save & Apply to Device.
  5. Navigate to Configuration › Tags & Profiles › Policy and click + Add.
  6. Set Profile Name = Policy-Corp, Status = Enabled.
  7. Under Access Policies: set VLAN = 100. Ensure Central Switching = Enabled and Central DHCP = Enabled.
  8. Click Save & Apply to Device.
  9. Navigate to Configuration › Tags & Profiles › Tags › Policy and click + Add.
  10. Set Tag Name = Tag-Corp. In the WLAN-Policy table, click + Add: select WLAN Profile = Corp-WiFi6, Policy Profile = Policy-Corp.
  11. Click Save & Apply to Device.
  12. Navigate to Configuration › Wireless › Access Points, click the target AP.
  13. Change Policy Tag = Tag-Corp. Click Update & Apply to Device.
✅ Expected Result: The SSID Corp-WiFi6 broadcasts on the target AP. Connecting clients receive an IP address on VLAN 100 via central DHCP. Verify under Monitoring › Wireless › Clients — VLAN column should show 100.
🔍 Verification: CLI: show wireless client summary | show wireless wlan summary
2

Configure a FlexConnect Site Tag for a Remote Branch

Medium
Scenario: A remote branch office has 2 Cisco APs connected over a WAN link. Configure them for FlexConnect with local switching so that client traffic is handled locally — even if the WAN link to the WLC goes down.
  1. Navigate to Configuration › Tags & Profiles › Flex and click + Add.
  2. Set Profile Name = Flex-Branch.
  3. Under VLAN, add a VLAN mapping: WLAN Corp-WiFi6 → VLAN 100 (the local VLAN at the branch switch).
  4. Click Save & Apply to Device.
  5. Navigate to Configuration › Tags & Profiles › AP Join and click + Add (or use existing).
  6. Set Profile Name = APJoin-Branch. Set NTP and syslog server IPs appropriate for the branch.
  7. Click Save & Apply to Device.
  8. Navigate to Configuration › Tags & Profiles › Tags › Site and click + Add.
  9. Set Tag Name = Tag-Site-Branch. AP Join Profile = APJoin-Branch. Flex Profile = Flex-Branch.
  10. Uncheck “Enable Local Site” — this declares the APs as remote (not directly connected to the WLC).
  11. Click Save & Apply to Device.
  12. Navigate to Configuration › Wireless › Access Points, select each branch AP.
  13. Change Site Tag = Tag-Site-Branch. Also ensure Policy Tag = Tag-Corp (from Exercise 1). Click Update & Apply to Device.
✅ Expected Result: Branch APs switch to FlexConnect mode (verify under Monitoring › Access Points — AP Mode column shows FlexConnect). Client traffic is locally switched at the branch without traversing the WAN. If WAN fails, clients remain connected.
🔍 Verification: CLI: show ap config general <ap-name> — confirm AP Mode: FlexConnect

Configure RADIUS 802.1X Authentication

Medium
Scenario: Security policy requires 802.1X Enterprise authentication for the corporate SSID. Configure RADIUS server at 10.1.1.100 (port 1812, secret: Cisco12345!) and apply it to the Corp-WiFi6 WLAN.
  1. Navigate to Configuration › Security › AAA › Servers / Groups › Servers. Click + Add.
  2. Set Server Address = 10.1.1.100, Auth Port = 1812, Acct Port = 1813, Key = Cisco12345!. Click Save.
  3. Navigate to AAA › Servers / Groups › Server Groups. Click + Add.
  4. Set Group Name = RADIUS-Corp, Group Type = RADIUS. Add 10.1.1.100 to the group. Click Save.
  5. Navigate to AAA › Method Lists › Authentication. Click + Add.
  6. Set Method List Name = dot1x-corp, Type = dot1x. Add Group = RADIUS-Corp. Click Save.
  7. Navigate to AAA › Method Lists › Accounting. Click + Add.
  8. Set Method List Name = acct-corp, Type = identity. Add RADIUS-Corp. Click Save.
  9. Navigate to Configuration › Wireless › WLANs, edit Corp-WiFi6.
  10. Security tab › Layer 2: Change to WPA2 Enterprise (802.1X). Set Auth Key Management = 802.1X. Set Authentication List = dot1x-corp.
  11. Save & Apply to Device.
  12. Edit Policy Profile Policy-Corp: ensure AAA Override = Enabled (allows RADIUS to push dynamic VLAN/ACL).
✅ Expected Result: Clients connecting to Corp-WiFi6 are prompted for credentials (EAP). Successful 802.1X authentication results in association; rejected credentials result in disconnection. Verify under Monitoring › Clients: Auth Method = Dot1x.
🔍 Verification: Troubleshooting › Radioactive Trace on the client MAC — look for RADIUS Access-Accept message in the log.

Create a Guest SSID with Local Web Authentication

Easy
Scenario: Create an open guest SSID called Guest-WiFi with a local captive portal. Guest clients should land on VLAN 200 and be redirected to a login page before accessing the internet.
  1. Navigate to Configuration › Security › Web Auth. Confirm Virtual IP is set (default 192.0.2.1). This IP must be non-routable on your network.
  2. Navigate to Configuration › Wireless › WLANs and click + Add.
  3. Set Profile Name = Guest-WiFi, SSID = Guest-WiFi, Status = Enabled.
  4. Security tab › Layer 2: set to None (open network). Layer 3: select Web Policy. Type = Webauth. Authentication List = default (local user database).
  5. Click Save & Apply to Device.
  6. Navigate to Configuration › Tags & Profiles › Policy and click + Add.
  7. Set Profile Name = Policy-Guest. VLAN = 200. Central Switching = Enabled.
  8. Click Save & Apply to Device.
  9. Navigate to Tags & Profiles › Tags › Policy, edit or create a tag. Add mapping: Guest-WiFi → Policy-Guest.
  10. Assign the Policy Tag to target APs via Configuration › Wireless › Access Points.
✅ Expected Result: Guest clients associate to Guest-WiFi without a password and are placed on VLAN 200. On first HTTP request, they are redirected to the Cisco captive portal login page. After login, internet access is granted.
🔍 Verification: Connect a test device to Guest-WiFi. Open a browser and navigate to any HTTP site — you should see the WLC login page.

Run a Radioactive Trace on a Failing Client

Easy
Scenario: A user reports their laptop (MAC: AA:BB:CC:DD:EE:FF) cannot connect to the corporate SSID. Use Radioactive Trace to capture the failure.
  1. Navigate to Troubleshooting › Radioactive Trace.
  2. Click + Add. Enter MAC address: AA:BB:CC:DD:EE:FF. Click Apply to Device.
  3. Click Start next to the MAC entry — debug collection begins.
  4. On the client device: forget the network and attempt to reconnect (or re-enable Wi-Fi).
  5. Wait 30–60 seconds to capture the full authentication sequence.
  6. Click Stop to end the trace.
  7. Click Log Download to save the trace log file (.txt).
  8. Open the log file and search for keywords: FAILED, REJECT, ERROR, TIMEOUT, policy.
  9. Common findings: RADIUS Access-Reject (wrong password/cert), DHCP timeout, Policy Tag missing WLAN mapping, PMF mismatch.
✅ Expected Result: A timestamped log file contains every control-plane event for the client MAC: probe, auth, assoc, 802.1X exchange, RADIUS response, DHCP, and policy application. The root cause of the failure is visible as an error or reject event.
🔍 Verification: In the log, a successful authentication shows: AUTHMGR-5-SUCCESS. A RADIUS rejection shows: Access-Reject.
6

Perform a Packet Capture on an AP Radio

Medium
Scenario: An 802.1X client is failing silently — Radioactive Trace shows the session starting but no RADIUS response. Capture the actual EAPOL frames over the air on AP AP-Floor2-01 to determine if EAP frames are reaching the client.
  1. Navigate to Troubleshooting › Packet Capture and click + Add.
  2. Set Capture Name = PCAP-EAP-Debug.
  3. Select AP Name = AP-Floor2-01.
  4. Select the radio the client is using: radio1 (5 GHz) or radio0 (2.4 GHz). Check Monitoring › Clients first to confirm the band.
  5. Set Direction = Both, Duration = 60 seconds, Buffer Size = 10 MB.
  6. Optionally set Inner MAC filter = AA:BB:CC:DD:EE:FF to capture only the target client's frames.
  7. Click Start. Immediately attempt to connect the client device.
  8. After 60 seconds (or click Stop early), click Download to save the .pcap file.
  9. Open in Wireshark. Apply filter: eapol. Analyze the EAP conversation — look for EAP-Request, EAP-Response, and whether EAP-Success or EAP-Failure is received.
✅ Expected Result: Wireshark shows the EAPOL 4-way handshake or EAP exchange. If EAP-Failure or no EAP-Success frame is visible, the issue is in the RADIUS exchange or the supplicant configuration. If no EAPOL frames at all are captured, the client may not be attempting 802.1X.
🔍 Verification: Wireshark filter eapol reveals: EAP Start → EAP-Request Identity → EAP-Response Identity → EAP-Success (or EAP-Failure).

Create and Apply a Custom RF Profile

Medium
Scenario: The 5 GHz band on your APs is using too-wide channels, causing co-channel interference. Create an RF Profile that limits DCA to channels 36–64, uses 40 MHz width, and caps Tx Power at 17 dBm.
  1. Navigate to Configuration › Tags & Profiles › RF and click + Add.
  2. Set Profile Name = RF-5GHz-Corp, Band = 5 GHz.
  3. Under RF Profile General: set Maximum Transmit Power = 17 dBm, Minimum Transmit Power = 5 dBm.
  4. Under DCA: ensure DCA is Enabled. Click Channel Assignment and select only channels 36, 40, 44, 48, 52, 56, 60, 64 (UNII-1 and UNII-2A). Deselect all DFS/UNII-3 channels.
  5. Set Channel Width = 40 MHz.
  6. Enable TPC (Transmit Power Control). Leave algorithm = Automatic.
  7. Click Save & Apply to Device.
  8. Navigate to Configuration › Tags & Profiles › Tags › RF and click + Add.
  9. Set Tag Name = Tag-RF-Corp. Set 5 GHz Band RF Profile = RF-5GHz-Corp.
  10. Click Save & Apply to Device.
  11. Navigate to Configuration › Wireless › Access Points. Select target APs and assign RF Tag = Tag-RF-Corp.
✅ Expected Result: APs using Tag-RF-Corp now operate only on channels 36–64 with 40 MHz channel width and a maximum of 17 dBm. Verify under Monitoring › Access Points — Channel column shows only channels in the 36–64 range.
🔍 Verification: CLI: show ap dot11 5ghz summary — verify channels and power levels.

Configure a Client ACL to Restrict Guest Traffic

Medium
Scenario: Guest clients on VLAN 200 must not be able to reach the corporate network (10.0.0.0/8). Create an ACL and apply it to the Guest Policy Profile.
  1. Navigate to Configuration › Security › ACL and click + Add.
  2. Set ACL Name = ACL-Block-Corporate, Type = IPv4 Extended.
  3. Click + Add to add ACE 1: Action = Deny, Protocol = IP, Source = any, Destination = 10.0.0.0 / 0.255.255.255. Sequence = 10.
  4. Click + Add to add ACE 2: Action = Permit, Protocol = IP, Source = any, Destination = any. Sequence = 20.
  5. Click Save & Apply to Device.
  6. Navigate to Configuration › Tags & Profiles › Policy, edit Policy-Guest.
  7. Under Access Policies: set IPv4 ACL = ACL-Block-Corporate (apply as Egress or both directions depending on requirement).
  8. Click Save & Apply to Device.
✅ Expected Result: Guest clients on VLAN 200 cannot ping or access any 10.0.0.0/8 address. Internet access (non-10.0.0.0/8 destinations) remains functional. Verify by trying ping 10.1.1.1 from a guest device — should timeout.
🔍 Verification: CLI: show ip access-lists ACL-Block-Corporate — match counters increment when guest traffic hits the deny rule.

Upgrade WLC Software to 17.9.5

Hard
Scenario: The WLC is running 17.9.3 and must be upgraded to 17.9.5. An SFTP server at 192.168.1.50 hosts the image. Perform the upgrade with AP pre-download to minimize downtime.
  1. Download the IOS-XE 17.9.5 image from Cisco Software Download (requires valid CCO/service contract). Filename format: C9800-universalk9_wlc.17.09.05.SPA.bin.
  2. Place the image on your SFTP server at 192.168.1.50 in the configured SFTP directory.
  3. Navigate to Administration › Software Management › Software Upgrade.
  4. Set Transfer Mode = SFTP, Server IP = 192.168.1.50, Username and Password for SFTP access, File Path = path to the .bin file.
  5. Click Download. Monitor the download progress bar — this may take 5–15 minutes.
  6. After successful download, verify the new version appears under Current Version on the upgrade page.
  7. Before activating the WLC: click AP Pre-download. This pushes the new image to all joined APs in the background.
  8. Monitor Monitoring › Wireless › Access Points — wait until all APs show Pre-downloaded status.
  9. Schedule or immediately click Activate. The WLC will save config and reload into the new image.
  10. WLC outage lasts approximately 5–7 minutes. APs enter standalone mode, existing client sessions on FlexConnect APs with local switching continue.
  11. After WLC comes back online, verify version: Administration › Software Management shows 17.9.5. Check all APs rejoin.
✅ Expected Result: WLC and all APs running IOS-XE 17.9.5. No permanent AP or client loss. APs that were pre-downloaded reload simultaneously with the WLC — typical downtime is 5–10 minutes total.
🔍 Verification: CLI: show version — confirms IOS-XE 17.09.05. GUI: Administration › Software Management shows 17.9.5.

Investigate RF Interference with CleanAir

Easy
Scenario: Users on Floor 3 report intermittent Wi-Fi drops every few minutes. You suspect a non-802.11 interferer. Use CleanAir and RF statistics to identify and mitigate the issue.
  1. Navigate to Monitoring › RF › RF Statistics. Filter by APs on Floor 3.
  2. Check Channel Utilization: values above 70% indicate congestion. Note which channels are most affected.
  3. Check Noise Floor: values worse than −85 dBm indicate a noise problem.
  4. Navigate to Monitoring › RF › Spectrum (CleanAir). Look for detected interferers.
  5. Note interferer Type (Microwave, DECT, Bluetooth, Video Camera, Jammer), Channel, Severity, and Duty Cycle.
  6. Identify the Closest AP to the interferer — use this to physically locate the interference source.
  7. Mitigation options: (a) Remove/relocate the interfering device. (b) Edit the RF Profile to exclude the affected channel from DCA. (c) Enable Event Driven RRM to trigger an immediate channel change when interference is detected.
  8. To exclude a channel: navigate to Configuration › Tags & Profiles › RF, edit the relevant RF Profile, remove the affected channel from the DCA channel list.
  9. To enable ED-RRM: in the RF Profile, enable Event Driven RRM with sensitivity = Medium.
✅ Expected Result: CleanAir identifies the interferer type and affected channel. After excluding the channel from DCA or relocating the interfering device, channel utilization and noise floor return to normal levels. Client drop rate decreases.
🔍 Verification: Monitoring › RF › RF Statistics — confirm Channel Utilization drops below 50% and Noise Floor improves to < −90 dBm after mitigation.
