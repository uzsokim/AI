#1HIGH Legacy/Insecure Protocols Enabled: CHAP

Area: Allowed Protocols: Default Device Admin

Detail: 'Default Device Admin' permits: CHAP. These protocols transmit credentials in a form vulnerable to offline dictionary attacks, MITM, and replay. LEAP is deprecated by Cisco. PAP/ASCII sends passwords in cleartext to the RADIUS server.

Recommendation: Disable CHAP. Use EAP-TLS for certificate-based mutual authentication, PEAP-MSCHAPv2 for password-based, or EAP-FAST for environments that cannot deploy certificates. Document any legacy exception with a risk acceptance record.

Top Remediation Priorities

Address findings in this order to achieve the greatest security improvement:

  1. Critical: Remove or restrict any PermitAccess rules with no conditions — these create full-bypass vulnerabilities.
  2. High: Ensure every authorization policy ends with a DenyAccess catch-all rule.
  3. High: Set ifAuthFail and ifUserNotFound to REJECT on catch-all authentication rules.
  4. High: Disable legacy protocols (PAP, LEAP, EAP-MD5) and replace with EAP-TLS / PEAP-MSCHAPv2.
  5. Warning: Apply DACLs to all access-granting authorization profiles for L3/L4 enforcement.
  6. Warning: Add session timeouts to all authorization profiles to force periodic re-evaluation.
  7. Info: Add descriptions to all policy sets and rules for audit traceability.
  8. Info: Enable CRL/OCSP validation for EAP-TLS to handle certificate revocation.
