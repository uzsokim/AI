📌 1. Overview

EIGRP (Enhanced Interior Gateway Routing Protocol) is Cisco's advanced distance-vector routing protocol, originally proprietary (Cisco IOS 9.21, 1993) and partially open-standardised in RFC 7868 (2016).

It combines the simplicity of distance-vector protocols with loop-prevention mechanisms and fast convergence borrowed from link-state protocols — often described as a hybrid or advanced distance-vector protocol.

⭐ 2. Key Features

Rapid ConvergencePre-computed backup routes (Feasible Successors) allow instant failover
Partial UpdatesOnly changes are sent, not the full routing table — saves bandwidth
VLSM / CIDRClassless — subnet mask is included in updates
Multiple ProtocolsIPv4, IPv6, IPX, AppleTalk (via PDMs)
Loop-FreeDUAL guarantees loop-free paths at every instant
Unequal-Cost LBVariance command allows traffic sharing over unequal paths
Neighbor AuthMD5 and SHA-256 (named mode) authentication
Route TaggingTag redistributed routes for policy control

PDM — Protocol Dependent Modules

EIGRP's modular architecture uses PDMs to handle different routed protocols (IPv4, IPv6, etc.) while sharing a common DUAL core and RTP transport engine.

📖 3. Key Terminology

TermDefinition
Reported Distance (RD)Metric a neighbor advertises to reach a destination (also: Advertised Distance)
Feasible Distance (FD)Best local metric to reach a destination (RD + link cost to neighbor)
SuccessorBest-path next-hop router; installed in the routing table
Feasible Successor (FS)Backup next-hop that satisfies the Feasibility Condition
Feasibility Condition (FC)FS's RD < FD of current Successor — guarantees a loop-free backup
Active routeRoute undergoing DUAL re-computation (Queries sent)
Passive routeStable route — not in re-computation; desired state
SIA (Stuck-in-Active)Router doesn't receive a Reply within SIA timer (default 90 s) → neighbor reset
Autonomous System (AS)EIGRP process identifier (1–65535); must match between neighbors
ℹ️ Remember: RD is what the neighbor tells you; FD is what you calculate (your metric to the destination). The Feasibility Condition compares the neighbor's RD to your current best FD.

🤝 4. Neighbor Discovery & Relationships

EIGRP uses Hello packets sent to multicast 224.0.0.10 to discover and maintain neighbors.

Requirements to Form a Neighbor Adjacency

  • Same AS number
  • Matching K-values (metric weights)
  • Reachable IP address on the same subnet
  • Authentication (if configured — must match)

Hello & Hold Timers

Interface TypeHelloHold
High-bandwidth (≥T1, point-to-point)5 s15 s
Low-bandwidth (multipoint, NBMA <T1)60 s180 s
⚠️ Hello and Hold timers do not need to match between neighbors. Each router advertises its own Hold timer in Hello packets.

Neighbor Table Entry Fields

  • Neighbor address & interface
  • Hold time (countdown)
  • Uptime
  • SRTT (Smooth Round-Trip Time)
  • RTO (Retransmission Timeout)

📦 6. EIGRP Packet Types (RTP)

EIGRP uses its own Reliable Transport Protocol (RTP) for guaranteed delivery of some packet types — no TCP/UDP involved.

TypeCodeReliable?Purpose
Hello5No (multicast)Neighbor discovery & keepalive
Update1YesSend routing changes
Query3YesAsk neighbors for a route during re-computation
Reply4YesRespond to a Query
Acknowledge6No (unicast)ACK for reliable packets (unicast Hello with seq=0)
SIA-Query10YesCheck if neighbor is still processing (avoid SIA reset)
SIA-Reply11YesRespond to SIA-Query — "I'm still working"
ℹ️ Reliable delivery = sent unicast with an ACK expected. If no ACK within RTO, retransmit up to 16 times before declaring the neighbor down.

⚙️ 7. DUAL Algorithm

The Diffusing Update Algorithm (DUAL) is the engine that selects loop-free paths and drives convergence.

Core Logic

  1. When a route is received, compare the neighbor's RD vs. current FD
  2. If RD < FD → satisfies Feasibility Condition → candidate for Feasible Successor
  3. Route with lowest FD is the Successor
  4. If Successor fails and an FS exists → instant failover (passive state maintained)
  5. If no FS → route goes Active → Queries sent to all neighbors

Convergence Path Decision

  Successor fails?
       │
       ▼
  FS exists?  ──YES──▶  Promote FS to Successor (instant, stays Passive)
       │
       NO
       │
       ▼
  Send QUERY to neighbors ──▶ Wait for REPLYs ──▶ Re-run DUAL ──▶ New Successor
🚨 Stuck-in-Active (SIA): If a Reply is not received within the SIA timer (default 90 s), the non-responding neighbor is reset. This is often caused by large topologies or slow links. Mitigate with EIGRP Stub.

📐 8. Composite Metric

EIGRP's metric uses a formula that considers up to five K-values.

Default Formula (K1=1, K2=0, K3=1, K4=0, K5=0)

Metric = 256 × [ (10⁷ / min_bandwidth_kbps) + cumulative_delay_10μs ]

Full Formula

Metric = 256 × [ K1×BW + (K2×BW)/(256−Load) + K3×Delay ] × [ K5/(Reliability+K4) ]
K-valueMetric ComponentDefault
K1Bandwidth1
K2Load0
K3Delay1
K4Reliability0
K5Reliability (denominator)0

Interface Default Values

InterfaceBandwidthDelayEIGRP Metric
Serial (T1 1.544M)1544 Kbps20,000 μs2,170,112
FastEthernet100,000 Kbps100 μs28,160
GigabitEthernet1,000,000 Kbps10 μs2,560
10 GigabitEthernet10,000,000 Kbps10 μs256
⚠️ Bandwidth is the minimum along the path; Delay is the sum of all delays. Changing K-values must be consistent across all routers in the AS — a mismatch prevents adjacency.

Modifying Metrics

! Change bandwidth (affects many protocols — prefer delay changes)
interface GigabitEthernet0/0
 bandwidth 500000

! Change delay only (microseconds ÷ 10)
interface GigabitEthernet0/0
 delay 100      ! 100 × 10 = 1000 μs

! Change K-values (must match all neighbors in AS)
router eigrp 100
 metric weights 0  1 0 1 0 0   ! TOS K1 K2 K3 K4 K5

⚖️ 9. Load Balancing

Equal-Cost Load Balancing

Default: up to 4 equal-cost paths (max 32 with maximum-paths 32).

Unequal-Cost Load Balancing (Variance)

EIGRP's unique feature — share traffic across paths with different metrics.

A route is eligible if: route_FD ≤ Successor_FD × variance
router eigrp 100
 maximum-paths 8    ! Allow up to 8 equal-cost paths
 variance 2         ! Include paths with FD ≤ 2× successor's FD
💡 The route must also be a Feasible Successor to be included in unequal-cost load balancing — it must satisfy the Feasibility Condition.

Traffic is proportionally distributed — a path with FD=2560 carries twice the traffic of a path with FD=5120 (inverse proportion to metric).

🗺️ 10. Route Summarization

Auto-Summary (Legacy)

EIGRP summarises routes at classful boundaries. Disabled by default since IOS 15. Causes black-holes with discontiguous subnets — best left off.

router eigrp 100
 no auto-summary    ! Recommended — ensure classless behaviour

Manual Summary

Applied per interface, outbound:

interface GigabitEthernet0/0
 ip summary-address eigrp 100 192.168.0.0 255.255.0.0
  • Creates a Null0 route for the summary prefix (AD 5) — prevents routing loops
  • Suppresses more-specific routes from being advertised out that interface
  • The metric used is the lowest FD among all component routes
⚠️ The Null0 discard route exists only while at least one component route exists. If all components disappear, the summary is withdrawn.

🔧 11. Classic Configuration

! Basic EIGRP process
router eigrp 100
 eigrp router-id 1.1.1.1        ! Manually set (recommended)
 network 10.0.0.0 0.0.255.255   ! Wildcard mask (or classful)
 network 192.168.1.0             ! Classful — matches 192.168.1.x
 no auto-summary
 passive-interface default       ! All interfaces passive by default
 no passive-interface Gi0/0      ! Selectively enable
 no passive-interface Gi0/1

! Tuning
 variance 2
 maximum-paths 6
 timers active-time 90           ! SIA timer (seconds)

Router-ID Selection Order

  1. Manually configured (eigrp router-id)
  2. Highest IP on a loopback interface
  3. Highest IP on an active physical interface
💡 Always set the router-ID manually to a loopback address for stability and predictability.

🆕 12. Named EIGRP (IOS 15.0.1M+)

Named mode is the recommended modern approach — it consolidates IPv4, IPv6, and VRF configuration under one process.

router eigrp CORP-EIGRP            ! Process name (not AS number)
 !
 address-family ipv4 unicast autonomous-system 100
  !
  af-interface default
   passive-interface
  !
  af-interface GigabitEthernet0/0
   no passive-interface
   hello-interval 5
   hold-time 15
   bandwidth-percent eigrp 100 50  ! Limit EIGRP to 50% of BW
  !
  topology base
   variance 2
   maximum-paths 8
   redistribute static metric 10000 10 255 1 1500
  !
  network 10.0.0.0 0.0.255.255
  eigrp router-id 1.1.1.1
 !
 address-family ipv6 unicast autonomous-system 100
  !
  af-interface GigabitEthernet0/0
   no passive-interface
  !
  topology base
  !
  eigrp router-id 1.1.1.1

🔄 13. Redistribution

! Redistribute from OSPF into EIGRP
router eigrp 100
 redistribute ospf 1 metric 10000 10 255 1 1500
 !         BW(Kbps) Delay(10μs) Reliability Load MTU

! Redistribute static routes
 redistribute static metric 1000 10 255 1 1500

! Redistribute connected networks
 redistribute connected metric 1000 10 255 1 1500

! Redistribute into OSPF from EIGRP
router ospf 1
 redistribute eigrp 100 subnets metric 20 metric-type E2
🚨 Mutual redistribution between two routing domains creates routing loops risk. Always use route tagging + distribute-lists or prefix-lists to prevent feedback loops.

🔐 14. Authentication

MD5 Authentication (Classic)

! Step 1 — Define key chain
key chain EIGRP-KEYS
 key 1
  key-string MyS3cretP@ss
  accept-lifetime 00:00:00 Jan 1 2024 infinite
  send-lifetime 00:00:00 Jan 1 2024 infinite

! Step 2 — Apply to interface
interface GigabitEthernet0/0
 ip authentication mode eigrp 100 md5
 ip authentication key-chain eigrp 100 EIGRP-KEYS

SHA-256 Authentication (Named Mode)

router eigrp CORP-EIGRP
 address-family ipv4 unicast autonomous-system 100
  af-interface GigabitEthernet0/0
   authentication mode hmac-sha-256 MyS3cretP@ss
💡 Key chains support multiple keys with time-based lifetimes — useful for key rotation without dropping adjacencies. The router tries the lowest key-id within send-lifetime first.

🌐 15. EIGRP for IPv6

Classic IPv6 EIGRP

! Enable IPv6 routing
ipv6 unicast-routing

! Create EIGRP IPv6 process
ipv6 router eigrp 100
 eigrp router-id 1.1.1.1      ! Mandatory — no IPv4 addr to derive from
 no shutdown                   ! Process starts shutdown by default

! Enable per interface (not network statement)
interface GigabitEthernet0/0
 ipv6 eigrp 100

Key Differences from IPv4 EIGRP

  • Uses multicast FF02::A instead of 224.0.0.10
  • Enabled per-interface (no network statement in classic mode)
  • Router-ID is mandatory (must be configured as 32-bit dotted decimal)
  • Process starts in shutdown state by default
  • Uses link-local addresses as next-hop

Named Mode IPv6 (Recommended)

router eigrp CORP
 address-family ipv6 unicast autonomous-system 100
  eigrp router-id 1.1.1.1
  af-interface GigabitEthernet0/0
   no passive-interface

🏠 16. EIGRP Stub Routing

Stub routers reduce Query scope — a hub router won't send Queries to stub spokes, preventing SIA and speeding convergence in hub-and-spoke topologies.

Stub Options

OptionWhat is advertised
stub connectedDirectly connected routes only
stub summarySummary routes only
stub staticStatic routes redistributed into EIGRP
stub redistributedRedistributed routes
stub receive-onlyNothing — only receives routes (pure leaf)
stub (default)connected + summary
! On the spoke router
router eigrp 100
 eigrp stub connected summary

! Verify
show ip eigrp neighbors detail   ! Shows "Stub Peer Advertising ..."
⚠️ A stub router will never be used as a transit router. Traffic destined through a stub neighbor may be black-holed — ensure the hub has a default or summary route pointing elsewhere.

Route Missing — Checklist

  • Is the network statement correct? (show ip protocols)
  • Is the interface passive? Remove if so
  • Is auto-summary causing classful summarization? (no auto-summary)
  • Is a distribute-list or prefix-list filtering the route?
  • Check topology table — is route Active or stuck? (show ip eigrp topology active)

Debug Commands

debug eigrp packets             ! All EIGRP packets (verbose!)
debug eigrp packets hello       ! Only Hello packets
debug eigrp packets update      ! Only Update packets
debug eigrp fsm                 ! DUAL finite state machine events
debug ip eigrp                  ! Route events
debug ip eigrp neighbor         ! Neighbor events

! Turn off all debug
undebug all
🚨 Use debug commands with caution on production routers — high CPU impact. Prefer debug eigrp packets hello (targeted) over debug eigrp packets (everything).

SIA Troubleshooting

show ip eigrp topology active   ! See routes stuck in Active state
debug eigrp fsm                 ! Watch DUAL state transitions

! Mitigation strategies:
! 1. Deploy EIGRP Stub on spoke routers
! 2. Use summarization to reduce Query scope
! 3. Split the AS at distribution layer (use redistribution)

Common Exam Traps

  • ❌ "Hello timers must match" → FALSE — they are independent
  • ❌ "Feasibility Condition: RD ≤ FD" → FALSE — it's strictly < (less than)
  • ❌ "EIGRP uses TCP for reliable delivery" → FALSE — uses its own RTP
  • ❌ "Variance can use any path" → FALSE — path must be a Feasible Successor
  • ❌ "auto-summary is off by default on old IOS" → FALSE — it was on before IOS 15
  • ✅ Bandwidth = minimum along path; Delay = cumulative sum
  • ✅ Router-ID is mandatory for EIGRP IPv6
  • ✅ Named mode uses 64-bit (wide) metrics internally

Verification Quick Commands

show ip eigrp neighbors           ! Adjacency health
show ip eigrp topology            ! Successor + FS per prefix
show ip eigrp topology all-links  ! All known paths
show ip route eigrp               ! Installed EIGRP routes
show ip protocols                 ! AS, K-values, networks, filters
show ip eigrp interfaces detail   ! BW%, hello/hold, auth status
show ip eigrp traffic             ! Sent/rcvd packet counts

Configuration Checklist

  1. Set router-ID manually (eigrp router-id x.x.x.x)
  2. Define networks with wildcard masks
  3. no auto-summary
  4. Set interfaces passive by default, explicitly allow EIGRP interfaces
  5. Enable MD5/SHA-256 authentication
  6. Configure stub on spoke routers
  7. Tune hello/hold timers if needed (WAN links)
  8. Apply manual summarization at boundaries
  9. Verify with show ip eigrp neighbors and show ip eigrp topology
